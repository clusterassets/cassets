# v0.7.0 Test Plan — Native-First Workstation Engine

Use a dedicated VS Code profile or Extension Development Host for workstation-setting tests.

## Automated

```powershell
npm install --package-lock-only
npm ci
npm run validate
npm run test:unit
npm run test:integration
npx vsce package --pre-release --out cassets-0.7.0.vsix
```

Expected unit baseline: **22 passing tests**.

## Manual Test A — Fresh VS Code profile

1. Create a clean VS Code profile with no Settings Sync.
2. Install the v0.7.0 VSIX.
3. Run `CAssets: Workstation Health` before initialization.
4. Run `CAssets: Initialize Developer Workstation`.
5. Confirm the approval dialog.
6. Open User Settings JSON.

Expected:

- only native VS Code professional settings are added when needed;
- settings already satisfied by VS Code defaults do not need to be written;
- no theme, font, keybinding, account, AI/provider or extension-specific settings are created;
- no extension is installed automatically.

## Manual Test B — Preserve developer choices

Before initialization, explicitly set examples such as:

```json
{
  "editor.minimap.enabled": true,
  "files.autoSave": "off",
  "explorer.compactFolders": true
}
```

Run workstation initialization.

Expected: all three explicit values remain unchanged and Workstation Health reports them as developer-owned/preserved.

## Manual Test C — Native capability audit

Run `CAssets: Native Capability Audit` in:

1. an empty/generic folder;
2. a Node project with no ESLint/Prettier;
3. a Node project that uses ESLint and Prettier;
4. a Python project.

Expected:

- generic/Node-native capabilities are reported as VS Code native;
- ESLint/Prettier are suggested only when repository ownership is detected;
- Python language/debug capability gaps are reported;
- nothing is silently installed.

## Manual Test D — Stack-aware performance

Open representative projects and run `CAssets: Optimize Workspace Performance`.

Expected examples:

- Node → `node_modules`, build/cache paths;
- Python → virtual-env/cache paths;
- .NET → `bin`, `obj`;
- Rust → `target`.

The command may initialize `files.watcherExclude` and `search.exclude` only when the workspace does not already own those settings.

## Manual Test E — Existing workspace settings win

Create `.vscode/settings.json` with custom `files.watcherExclude` and/or `search.exclude` values before running optimization.

Expected: DevReady preserves them rather than replacing them.

## Manual Test F — Restricted Mode

Open an untrusted workspace.

Expected:

- Workstation Health and native capability inspection can remain informational;
- stack-aware workspace writes are blocked until trust is granted;
- no repository baseline writes occur.

## Regression

Re-run v0.6 behavior:

- existing files are not overwritten;
- intentionally deleted generated templates stay deleted after re-scan;
- explicit Restore Missing Generated Templates recreates them;
- environment-variable detection exposes names only;
- repository command execution still requires explicit confirmation;
- extension recommendations remain advisory only.
